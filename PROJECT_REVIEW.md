**Project review — 13 October 2026**

The main risks are authorization, tenant-wide administration, and asynchronous workflow correctness. Address these before adding more AI features. The API/frontend separation and the resume-skill confirmation flow are useful foundations, but several advertised behaviors differ from the implementation.

Reviewed the tracked API, frontend, services, models, migrations, configuration, tests, Dockerfile, deployment workflow, and documentation. No application source was changed. n8n workflow exports, GCP configuration, production settings, and live execution records are absent, so the deployed workflow configuration could not be verified. No hosted database test or production mutation was run.

**Validation**

- API Release build and 11 existing local tests passed using `dotnet test JobTracker.Api.Tests/JobTracker.Api.Tests.csproj --no-restore --filter 'FullyQualifiedName!~MultiTenantIsolation' -c Release`.
- The tenant-isolation test was deliberately excluded because it contains hosted database credentials and opens that database directly.
- Frontend production build passed. Main JavaScript chunk: 566.04 kB, 180.63 kB gzip; Vite reported its size warning.
- Frontend lint completed with zero errors and 11 warnings. Warnings include missing effect dependencies and synchronous state updates in effects. No Rules of Hooks violation was reported.
- A temporary local console harness called the existing controllers/services using EF InMemory. It reproduced the unauthorized requirements update, inconsistent fit scores, stale activity after saving notes, incorrect interview-round targeting, missing AI marker, duplicate skill exception, and incomplete cross-user skill migration. The harness was removed after verification.
- Numeric strings such as `{ "round": "2" }` are accepted by ASP.NET's web JSON defaults. The frontend passing a string round is an inconsistent contract, but it is not currently a request-deserialization bug.

**Findings, ordered by urgency**

1. **P0 — Credentials are committed.** [Tenant-isolation test](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api.Tests/MultiTenantIsolationTest.cs:15) contains a plaintext hosted PostgreSQL password. The tracked [development settings](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/appsettings.Development.json:1) also contain a database password, a Supabase service-role JWT, and an automation key. These were inspected without testing their validity. Treat them as compromised: rotate them, remove their values from tracked files and Git history, and put replacements in user-secrets/hosting secrets. `.gitignore` does not remove files already tracked. Do not reproduce their values in issues or logs.

2. **P1 — Application requirements can be changed without authentication.** [InternalController.UpdateRequirements](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/InternalController.cs:61) omits the automation-key check used by its other actions. There is no controller authorization attribute or fallback authorization policy. Anonymous requests also make the tenant filter inert. A caller with an application ID can change its experience requirement, seniority, education, or job embedding. Local reproduction returned `NoContentResult` and persisted a change with no JWT or automation key. Apply a controller-wide automation authentication policy that rejects missing/empty configuration, rather than repeating guards in individual actions. Ordinary tenant access should fail closed; give trusted internal operations an explicit cross-tenant path.

3. **P1 — Global skill merges lose other tenants' associations.** [AdminController.MergeSkills](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/AdminController.cs:149) reads ApplicationSkills/UserSkills through filters for the logged-in admin, migrates only those visible links, then deletes the globally shared source skill. The PostgreSQL migration declares cascading deletes from Skills to both link tables. Other tenants' source links therefore disappear without receiving the target link. Local reproduction showed the admin receiving a target association and the other user receiving none while the source skill was deleted. The usage counts on the admin page are also tenant-scoped. Use explicit cross-tenant queries for this authorized operation and its counts. Preserve importance, proficiency, and evidence when merging; the current new link objects reset all of them. Define a conflict rule when a target link already exists, and commit the merge atomically.

4. **P1 — The demo database switch breaks Identity and callbacks.** [Program.cs](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Program.cs:35) replaces the entire Identity-backed AppDbContext with a per-token InMemory database for test-role requests. Login and startup create the test user in PostgreSQL, but the authenticated sandbox has no Identity user. Profile/email/password operations therefore cannot find that user. Anonymous n8n callbacks choose PostgreSQL and cannot find applications/resumes created in the sandbox. Real Supabase storage and real workflows are still used by demo requests. Separate Identity persistence from sandbox application data, and either simulate automation/storage for demo sessions or provide an explicitly isolated persisted demo environment. Bound sandbox lifetime; every login currently creates another in-process database, with no eviction policy.

5. **P1 — Workflow acknowledgement is treated as completed extraction.** [Skill trigger](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/ApplicationsController.cs:118) and [interview trigger](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/ApplicationsController.cs:336) write `succeeded` when the outbound webhook returns any successful HTTP status. The callbacks that save skills/questions do not complete an associated run. If n8n responds immediately, the UI stops polling before results exist; if it waits for the last node, the 10-second skill request timeout can mark a still-running workflow failed. n8n explicitly supports both response modes. [Webhook documentation](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/).

   Persist a run with `queued → dispatched → running → succeeded/failed`, return its ID, and let a successful callback transaction mark that run complete. HTTP acknowledgement should mean dispatched. Record failure through an explicit workflow failure callback, with a deadline for runs that never report back. Resume state is closer to this design, but its trigger-side timeout can still overwrite a successful callback with `failed`.

6. **P1 — Application polling races the first log entry and retries.** [ApplicationsContext.pollExtraction](C:/Users/mcs/Desktop/job-tracker/client/src/state/ApplicationsContext.jsx:52) retries only `triggered`; a first response with `status: null` stops polling. The initial log is written inside Task.Run after Create has saved the application, so null is reachable. [Detail polling](C:/Users/mcs/Desktop/job-tracker/client/src/pages/ApplicationDetail.jsx:307) has the same stop condition. During retry, the previous succeeded/failed log may remain the latest until the background task writes its new entry, causing polling to stop on the previous run. Persist a queued run before returning, poll by run ID, and treat unknown/in-progress states as pending within a bounded elapsed-time deadline. Resume timeouts need server-side recovery: `RetryExtraction` returns conflict forever if an interrupted run remains `triggered`.

7. **P1 — Fire-and-forget work is lost on process shutdown.** [Applications Task.Run](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/ApplicationsController.cs:98) and [resume Task.Run](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/ResumesController.cs:109) have no durable queue. A restart/redeploy after the user action commits can lose the webhook. Initial log saves happen outside the try/catch, so a database failure there also ends the unobserved task without a failure entry. Scoped service resolution depends on ambient request state, which is particularly problematic for demo routing. Use an outbox row committed with the application/resume and a hosted worker that dispatches pending rows. Persist retries, jittered backoff, attempt limits, and dead-letter state. A second message broker is unnecessary at this scale.

8. **P1 — Interview questions are written into the wrong round.** [SetInterviewQuestions](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/InternalController.cs:121) always selects the newest interview StageDetail and ignores the requested round during selection. The frontend exposes generation on the *new-round* slot, so requesting round 3 when rounds 1 and 2 exist appends questions to round 2. Local reproduction requesting round 1 with two records wrote into round 2. Create the round first and pass its immutable StageDetailId through the trigger and callback. Validate its application/stage, and support generation on existing rounds too.

9. **P1 — Deleted or demoted users retain JWT authority.** [JWT validation](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Program.cs:77) validates the token's cryptography/lifetime but never checks whether the account still exists or whether its roles/security version changed. [Tokens](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Services/ITokenService.cs:32) default to seven days. Deleting an account, changing a password, or demoting an admin therefore does not revoke existing bearer tokens. A deleted user's token can create new orphan applications because UserId has no Identity FK. Use a revocable session/security-version check and shorter access-token lifetime; invalidate sessions on deletion and security-sensitive changes.

10. **P2 — Board and detail pages calculate different fit scores.** [List](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/ApplicationsController.cs:41) uses IFitScorer's weighted/semantic calculation. [GetDetail](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/ApplicationsController.cs:212) uses unweighted skill count. Local reproduction: owning the importance-3 skill and missing the importance-1 skill yields 75% on the board and 50% in detail. Detail refreshes also overwrite the shared board row with that 50%. Use IFitScorer everywhere and return its breakdown. The card tooltip/detail explanation should describe the same metric the API computes.

11. **P2 — Saving posting skills destroys extraction importance.** [SetApplicationSkills](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/SkillsController.cs:118) replaces every link with objects whose Importance defaults to zero. The scorer treats zero as weight 1. Saving an unchanged tag list therefore turns required and preferred skills into equal low-weight skills; the existing requirements embedding can also remain attached to a changed skill set. Return/edit structured skill objects, preserve retained metadata, assign a documented default to new skills, and invalidate or regenerate the relevant embedding when requirements change.

12. **P2 — Proficiency ratings do not affect the advertised results.** [MySkills copy](C:/Users/mcs/Desktop/job-tracker/client/src/pages/MySkills.jsx:72) says fit and Skills Gap read proficiency levels. [FitScorer](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Services/IFitScorer.cs:18) reads skill IDs only; Skills Gap also uses binary ownership. Beginner and Expert produce identical results. Either define and implement a transparent proficiency rule or present ratings as personal notes and remove claims that they affect scoring. Self-rated levels should not imply a calibrated probability of hiring.

13. **P2 — Overlapping skill edits lose changes.** [MySkills add/remove](C:/Users/mcs/Desktop/job-tracker/client/src/pages/MySkills.jsx:45) each submit the full names array derived from current rendered state. [SkillLevelEditor](C:/Users/mcs/Desktop/job-tracker/client/src/components/SkillLevelEditor.jsx:18) permits operations on different rows concurrently, using a single busyRow value. Two removals started before either response each send a list containing the other's removed skill; one skill reappears. A list replacement can also overwrite a concurrent level update. Prefer per-skill POST/DELETE operations, optimistic concurrency for replacements, or serialize mutations. Keep per-row pending state as a Set rather than one scalar.

14. **P2 — Tag editor drafts do not follow updated server results.** [TagEditor](C:/Users/mcs/Desktop/job-tracker/client/src/components/TagEditor.jsx:6) copies initialSkills only at mount. [ApplicationDetail](C:/Users/mcs/Desktop/job-tracker/client/src/pages/ApplicationDetail.jsx:639) keys it by application ID. If it mounts before extraction becomes visible, later setRequiredSkills updates leave the same editor holding the old empty array; saving can erase extracted skills. Use a controlled editor or synchronize server versions when the draft is clean. Preserve dirty user input instead of resetting blindly. StageDetailForm has a related stale-initialFields risk when generated prep notes arrive while a form is open; a whole-JSON save can overwrite the callback's additions. Patch fields with a version check and store generated questions separately.

15. **P2 — Question polling uses unrelated activity as completion and survives route changes.** [startQuestionsPoll](C:/Users/mcs/Desktop/job-tracker/client/src/pages/ApplicationDetail.jsx:391) declares success whenever timeline length exceeds the baseline. A status change satisfies this condition even if generation failed. Cleanup runs on unmount only, not when the route's application ID changes; a pending response for A can replace B's timeline/stage details. Poll the generation run and target round, cancel on ID change, and guard in-flight responses by run/application identity. Prefer scheduling the next request after the previous request completes instead of an overlapping async setInterval.

16. **P2 — Stage-note edits do not update application activity.** [UpsertStageDetail](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/ApplicationsController.cs:259) saves FieldsJson without a timeline event or UpdatedAt change. [Alerts](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/AnalyticsController.cs:43) and internal stale reminders consider timeline timestamps only. Local reproduction: editing notes today left the application stale. Separate last user activity from last employer response and last automation activity. Record user edits and use the appropriate timestamp for each alert. Generated interview notes should not count as an employer reply.

17. **P2 — First generated questions are rendered as user notes.** [Callback](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/InternalController.cs:146) includes the AI marker only when appending to nonempty prepNotes. [Renderer](C:/Users/mcs/Desktop/job-tracker/client/src/components/StageAccordion.jsx:22) treats everything preceding a marker as user notes. An initial generation into empty notes therefore appears under “Your notes,” without the AI question display. Local reproduction confirmed the missing marker. Prefer a generatedQuestions field/table with provenance instead of parsing a free-text delimiter.

18. **P2 — Account deletion leaves personal data and files behind.** [DeleteUser](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/AdminController.cs:52) deletes applications and the Identity user only. Resumes, UserSkills, UserProfile (including resume text/embedding), storage objects, and automation logs remain; there are no Identity relationships to cascade these application-owned rows. The database and storage deletions are not one coordinated process, and IdentityResult is ignored. Implement a deletion job that revokes sessions, deletes all owned records, retries storage cleanup, and reports partial failures. Retain only deliberately anonymized audit metadata.

19. **P2 — Resume callbacks can overwrite a newer profile and accept invalid vectors.** [SetResumeExtraction](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/InternalController.cs:31) immediately writes the user profile for every callback. Upload A then B; if A finishes last, A replaces B's profile. Failure-like empty results also reset text/experience, while absent embedding/seniority can retain old values. Any nonempty resume vector is accepted even though the PostgreSQL column requires 1536 dimensions; an invalid callback becomes a database error. Keep extracted data per resume, select an explicit active resume/version, reject outdated run IDs, and validate vector dimensions/finiteness before saving. The user-skill confirmation gate currently protects skill membership only, not these profile writes.

20. **P2 — Duplicate LLM skills can crash a callback.** [Automation skill callback](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/InternalController.cs:95) iterates the original DTO list after resolving deduplicated names. “Docker” and “docker” resolve to one SkillId but produce two identical ApplicationSkill keys. Local reproduction threw InvalidOperationException from EF's tracker. Normalize/group the DTOs once and choose a documented importance merge rule. Validate null names and importance range. Both skill resolvers also use select-then-insert against a unique global name index, so simultaneous creation of the same new skill can fail; use a PostgreSQL upsert or recover from unique conflicts.

21. **P2 — n8n health checking targets the wrong standard path and can erase frontend state.** [N8nHealthChecker](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Services/In8nhealthchecker.cs:22) requests `/health`; standard n8n endpoints are `/healthz` and `/healthz/readiness`. Unless the deployment explicitly provides an alias, this reports a healthy instance unreachable. The development JSON nests a property named `N8n:BaseUrl` inside N8n, producing an effective `N8n:N8n:BaseUrl` instead of the key the service reads. [n8n monitoring documentation](https://docs.n8n.io/hosting/logging-monitoring/monitoring/).

   [HealthGate](C:/Users/mcs/Desktop/job-tracker/client/src/components/HealthGate.jsx:115) initially renders children, then replaces them after a failed check. This unmounts AuthProvider, ApplicationsProvider, routes, and open forms; they remount after recovery/timeout. A workflow outage can therefore discard user input while CRUD is available. Show automation degradation without unmounting the app. Use separate API liveness/readiness and workflow health signals. The Axios request has no timeout, so the advertised 45-second give-up deadline is not a hard bound on a hung initial request.

22. **P2 — Admin role operations can remove access without completing the replacement.** [SetUserRole](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/AdminController.cs:39) removes existing roles before validating/adding the requested role and ignores IdentityResult. CreateUser also ignores assignment failure. Self-delete, self-demotion, and loss of the last admin are blocked only in the UI or not blocked at all. Validate the role allowlist first, preserve an administrator, enforce safeguards server-side, and handle failures transactionally. The UI identifies self by email from local auth state, which can be stale after a profile email change; use immutable user ID.

**Secondary defects and limits**

- [Status handlers](C:/Users/mcs/Desktop/job-tracker/client/src/pages/ApplicationDetail.jsx:358) and Dashboard allow overlapping optimistic writes, do not apply the server response, and roll back from stale captured state. An older failure can undo a newer success. Timeline and UpdatedAt also stay stale after a successful detail status change. Serialize changes per application, apply returned canonical data, and refresh the timeline.
- [ApplicationsProvider](C:/Users/mcs/Desktop/job-tracker/client/src/state/ApplicationsContext.jsx:12) does not cancel/sequence list requests. A delayed initial refresh can overwrite a just-added application, and StrictMode produces an additional setup cycle in development. Background poll timers have no provider cleanup. Memoize shared actions before completing effect dependencies; adding an unstable updateApplication dependency directly would restart detail polling on every provider render. [React effect documentation](https://react.dev/reference/react/useEffect).
- [SkillPicker](C:/Users/mcs/Desktop/job-tracker/client/src/components/SkillPicker.jsx:14) debounces request starts but does not discard outdated responses. AdminSkills table loading has the same search/page race. Typing to invalidate a selected picker value also triggers the value effect, which can clear the newly typed search. Separate selected value from query and guard request versions.
- [Skills Gap](C:/Users/mcs/Desktop/job-tracker/JobTracker.Api/Controllers/SkillsController.cs:163) takes the top 15 by raw frequency before the UI ranks importance or trends. A rare must-have can be omitted despite a larger weighted score; rising/fading results are restricted to the same frequency shortlist. Return all eligible aggregates or calculate each ranking server-side, with extraction coverage and sample-size thresholds.
- “No reply” is inferred from timeline count rather than explicit employer response. Arbitrary notes/status corrections/AI generation can change this classification. Track first/last employer response explicitly, with a manual “response received” action if email integration remains absent.
- Empty interview stages produce both a generic current-stage form and the explicit new-round form in buildStageEntries. Round fields are editable strings and labels are derived from creation order, not a stored round identity. Use one new-round slot and stable round records.
- Interview `datetime-local` values are stored without a timezone; date-only fields are displayed using new Date on a UTC-parsed date string. This can shift interviews across devices/timezones and shift calendar dates in negative UTC offsets. Store interview instants plus their intended zone; format date-only values as calendar dates.
- Resume uploads return no ExtractionStatus, and ResumeManager opens the extraction modal unconditionally, even when automation is not configured. The modal cannot close during extraction. After timeout, the list does not poll and a triggered row cannot be reopened through its status label. Return automation state, allow closing immediately, and provide reopen/retry actions for queued, failed, and timed-out runs.
- ConfirmSkills stores selected names but discards their resume evidence/strength; replacing user skills also discards evidence on retained names. Proposed alreadyClaimed matching is case-sensitive although the resolver normalizes names. Persist evidence with its source/version if it serves a user-facing purpose, and normalize proposal comparisons.
- Storage paths include raw file.FileName and are interpolated into request URIs without segment encoding. Names containing `#`, `?`, or separators can alter the addressed object path. Use generated object keys with validated extensions and retain the original display name separately. MIME checks trust client metadata; storage upload/save and delete/save failures can leave orphan files or broken rows. Reconcile these operations with retryable cleanup.
- API validation is uneven: stage enum/field schema, round range, importance bounds, text lengths, URLs, and alert thresholds are mostly unrestricted. A supplied StageDetailId is not checked against req.Stage. Validate contracts at their boundaries, particularly automation payloads; use the existing API error mechanism for actionable validation responses.
- Login uses CheckPasswordAsync with no rate limiter or failed-attempt lockout progression. Add throttling and explicit lockout handling for the deployed login endpoint.
- Internal webhook calls do not attach the X-Automation-Key documented in README; the named n8n client also has no configured authentication header. Header-authenticated n8n triggers would reject these calls. Actual workflow authentication is unverified because exports are absent. Configure outbound authentication explicitly and test it separately from callback authentication.
- FitScorer loads all applications/links and scans links for each application, rather than grouping once; several analytics/admin paths load entire tables before paging. Add tenant/date/status indexes and paginated application queries when data volume warrants it. No vector index is needed for the current pairwise scoring implementation.
- The README claim that unnormalized vectors make the implemented cosine calculation wrong is inaccurate: CosineSimilarity divides by both magnitudes. Normalize embeddings if required by the chosen storage/search operation, but document the actual mathematics. The hard-coded 0.3–0.9 rescaling and 70/30 blend are heuristics, not validated hiring probabilities.

**DevOps improvements, in implementation order**

1. Fix committed secrets and internal authorization; add secret scanning and controller-level tests for every internal action.
2. Add durable AutomationRun/Outbox records, run correlation IDs, idempotent callbacks, workflow deadlines, bounded retries, and a manual retry/dead-letter view. Unify the three trigger implementations around one dispatcher. Do not use historical triggered log events as a “currently running” list; derive current state per run.
3. Export sanitized n8n workflows into version control. Include payload schemas, prompt/model/embedding versions, callback routes/methods/auth, error workflows, and representative fixtures. Test acknowledgement-before-callback, duplicate callback, old retry finishing late, missing callback, deletion during a run, and restart before dispatch.
4. Run CI on pull requests as well as main pushes. The current workflow only gates deployment after main has changed, does not include frontend build/lint, and does not trigger on its own workflow changes. Add separate fast local tests and isolated PostgreSQL+pgvector integration tests; never depend on hosted user data. Existing weight/normalization tests repeat the arithmetic/normalization instead of calling the relevant service paths, so they would not catch several findings above.
5. Add controlled schema migration before releasing dependent code, deployment concurrency limits, a post-deploy readiness smoke test, and a documented rollback procedure. The repository currently runs neither migrations nor a post-deploy verification. Use expand/contract migrations when rollback must remain possible.
6. Track structured request/run IDs, completion latency, failure/retry rates, pending-run age, and dependency status. Bound and page automation logs, and redact signed URLs, resume text, tokens, and credentials. Add database/storage backup and restore verification.
7. Add a reproducible local development setup with fake automation fixtures and optional PostgreSQL/pgvector+n8n containers. Keep the Windows Dockerfile only if Windows container deployment is an actual supported path. If infrastructure reproducibility is a portfolio goal, version GCP setup, backup, and upgrade configuration; naming four providers alone does not establish that reproducibility.

**Simplification and removals**

- Remove the unused SkillsAndResume page and unused React/Vite starter assets. Keep existing URL redirects; the old page also expects string skills while getMySkills now returns objects.
- Consolidate duplicate skill-resolver implementations and duplicate/nested application/skill DTOs. Generate frontend contracts from OpenAPI or adopt schemas that check request/response shape in tests.
- Consolidate JobEmbedding and RequirementsEmbedding around the embedding actually consumed by scoring. JobEmbedding, application education/seniority/experience requirements, UpdateUserProfileRequest, and stored evidence currently have no complete user-facing path; either implement their stated purpose or stop collecting/maintaining them.
- Hide rising/fading charts until sufficient successfully extracted applications exist in both comparison windows. Small-sample trends currently consume space without supporting a dependable decision.
- Remove the blocking health screen and blocking extraction modal behavior. Preserve health diagnostics and workflow progress as nonblocking status.
- Keep proficiency ratings only with a defined purpose and accurate explanation. Remove the repeated board-score refresh after changing a level while the scorer remains level-independent.
- Keep terminal states distinct; rejected, withdrawn, accepted, and declined preserve meaningful outcomes. Reduce visual clutter through filtering rather than deleting those distinctions.
- Defer cover-letter generation and public share links. Reliable tracking, deadlines, data correction, export, and traceable automation provide more direct value first.

**Repair order:** credentials/authorization → cross-tenant merge and session revocation → demo separation → durable workflow runs/callback correlation → scoring/metadata consistency → frontend concurrency and activity semantics → CI/deployment reproducibility → workflow-oriented product additions.
